# 无人机调度 Demo

这是一个基于规则、轻量优化与启发式的无人机调度原型，读取 `无人机调度结构.json`，输出候选机场、合规机场、指派结果、时间轴、方案对比和规则审计。

## 算法流程

1. 读取带注释的 JSON，并去掉 `//` 注释。
2. 解析机场、无人机、天气、工单对象和作业航点。
3. 按气象、机场状态、无人机状态、起飞电量、覆盖半径等规则过滤候选机场。
4. 先用规则过滤不可执行机场，再对均衡方案做全局机场分配优化；任务规模较大时自动采用带负载项的贪心近似。
5. 按机场聚合任务，以最近邻生成初始航线，再用 2-opt 做局部改进。
6. 在固定航线顺序下，用动态规划寻找满足单架次上限的最少连续分段。
7. 依据航程、速度、作业时长、准备时间和安全冗余估算单架次耗时。
8. 按方案阈值拆分接力段，并输出时间轴与电量状态。
9. 生成三套方案：均衡、时效优先、电量稳健。

## 实现细节

### 1. 数据解析

- `load_structure()` 先去掉 JSON 注释，再用标准 `json.loads()` 解析。
- `parse_airports()` 从顶层 `airport` 数组读取机场台账。
- 每个机场同时绑定：
  - 机场自身字段：状态、半径、自检标记、风速、雨量、当前任务等
  - 无人机字段：电量、速度、续航、充电时长、充电剩余
  - 顶层天气表：用于周期工单的天气判定
- `parse_targets()` 从 `work_order.woder_order_detail` 取每个作业对象，把 `obj_data` 中的航点平均成一个中心点，同时保留原始航点列表。

### 2. 候选机场筛选

对每个机场都会先跑 `airport_ready()`，核心判断是：

- 机场状态是否正常
- 无人机是否待机，或者是否处于可快速恢复的充电状态
- 起飞电量是否满足 `P006`
- 当前任务是否可抢占
- 气象是否满足 `weather_ok()`

再结合 `inspection_radius` 判断是否覆盖目标点。

### 3. 气象判定

`weather_ok()` 的逻辑是：

- 先选目标日期对应的天气；找不到就取第一天
- `weather` 文本命中雷暴关键词直接禁飞
- 周期工单遇到中雨/大雨/暴雨禁飞，小雨预警
- 周期工单风力级数超过阈值则禁飞
- 机场开启自检时：
  - 用 `airport.wind_speed` 判断风速是否 `<= 8m/s`
  - 用 `airport.rainfall` 换算后的 `mm/h` 判断是否 `<= 2.5mm/h`

### 4. 指派规则

`choose_airport()` 会给每个作业对象的每个机场打分：

- `balanced`：优先负载更小，其次更近
- `energy_first`：优先更省电，其次更近
- `time_first`：优先更近

如果机场不合规，直接淘汰。

### 5. 航线和耗时

单架次时长按下面的式子算：

```text
总时长 = 准备时间 + 飞行时长 + 作业时长 + 安全冗余
飞行时长 = 航程 / 飞行速度
作业时长 = 对象数 × 30min
安全冗余 = max(飞行时长 × 比例, 3min)
```

其中航程是从机场到航点、航点之间、再返航的总和。

### 6. 接力拆分

如果单架次超过方案允许上限，就会拆成多段接力：

- 先按机场聚合任务
- 对同一机场的任务按最近邻顺序排序
- 如果单段过长，就继续按航点拆段
- 每段都重新算飞行、作业、冗余和电量剩余

接力判定依赖三条电量线：

- 返航线
- 接力线
- 预警线

### 7. 时间轴

当前实现不是“纯倒排最优解”，而是：

- 从 `start_date` 开始生成时间轴
- 先应用 `P012` 的响应锚点，保证最早起飞不会早于响应目标
- 每个机场/无人机资源按完成时间顺序串行排布
- 若计划超过 `end_date`，则标记为超窗

### 8. 方案生成

脚本会跑三遍同一工单：

- `balanced`
- `time_first`
- `energy_first`

然后：

- 过滤掉 `partial/infeasible` 方案
- 去掉签名完全相同的重复方案
- 最后选一个推荐方案

### 9. 输出构造

`build_table_output()` 会把结果整理成 10 个输出块：

- 候选机场集合
- 合规机场集合
- 指派结果
- 起飞时间 / 预计完成时间
- 航线 `route_id`
- 单架次时长
- 方案对比
- 决策依据
- 不可行原因
- 抢占 / 接力 / 协同决策

## 用到的算法

- **规则过滤**：先把不满足气象、状态、电量、半径的机场剔除。
- **贪心指派**：每个作业对象选择当前最合适的机场，不做全局最优求解。
- **最近邻排序**：同一机场内的任务按当前位置到下一个点最近的原则排序。
- **接力拆分**：当单架次超出阈值时，按航点继续拆成多段执行。
- **串行排程**：同一机场和无人机资源按完成时间顺序依次排布。
- **启发式打分**：三套方案分别偏向距离、时效、电量余量。

这套实现采用“规则 + 优化 + 启发式”的混合方式：安全与可行性由规则负责，均衡方案的机场分配使用内置的全局离散分配优化，航线使用 2-opt 局部改进；它仍然不是保证数学全局最优的完整 MILP/VRP 求解器。

### 8.1 优化器开关

可在 `dispatch_params`、`baseline_params`、`params` 或 `work_order.dispatch_params` 中设置：

```json
{
  "P_ENABLE_ASSIGNMENT_OPTIMIZER": true,
  "P_ENABLE_SORTIE_OPTIMIZER": true,
  "P_ENABLE_SCHEDULE_OPTIMIZER": true,
  "P_ASSIGNMENT_EXACT_LIMIT": 12,
  "P_ASSIGNMENT_NODE_LIMIT": 200000
}
```

关闭 `P_ENABLE_ASSIGNMENT_OPTIMIZER` 后，均衡方案回退到原有逐对象机场指派。关闭 `P_ENABLE_SORTIE_OPTIMIZER` 后，架次和接力回退到顺序贪心/平均切分；关闭 `P_ENABLE_SCHEDULE_OPTIMIZER` 后，同一资源按原架次序号排程。所有方案始终保留规则过滤、续航和时间窗复核。

## 核心规则

### 气象

- `P001` 周期工单风力硬校验
- `P001` 机场自检风速阈值
- `P002` 周期工单降雨禁飞和小雨预警
- `P002` 机场自检雨量阈值
- `P003` 能见度阈值占位
- `P004` 温度记录
- `P005` 雷暴禁飞

### 资源与状态

- `P006` 起飞电量门槛
- `P007` 单架次时长上限
- `P008` 机场状态、无人机待机状态
- `P009` 单机日出勤上限
- `P010/P011` 安全冗余
- `P018` 充电中无人机可用判断
- `P037/P038/P039/P040/P043` 满电续航、速度、作业时长、准备时间、充电时长

### 调度协同

- `P012` 响应时效锚点
- `P013` 抢占判断
- `P014` 不可抢占白名单
- `P015` 自动/人工/排班模式
- `P028` 协同拆分
- `P029` 多对象协同触发
- `P041` 覆盖半径预筛
- `P042` 顺路合并占位

## 方案差异

- `balanced`：优先最近且负载更均衡
- `time_first`：优先更短完成时间
- `energy_first`：优先更高电量余量

三套方案共享同一套硬约束，只在机场选择、拆分偏好和电量安全线方面不同。

## 可配置参数

脚本里所有非业务 JSON 直接提供的算法参数，都集中在 `CONFIGURABLE_PARAMS` 中，可在 JSON 的 `dispatch_params`、`baseline_params`、`params` 或 `work_order.dispatch_params` 中覆盖。

常见可配项包括：

- 气象阈值
- 起飞电量门槛
- 安全冗余
- 响应时效
- 抢占阈值
- 续航与充电默认值
- 三套方案的电量线

```bash
python3 core_dispatch_demo.py

```
